Changelog

All the notable changes to the extension, from the latest version to the first.

1.5.0 - 2026-10-10

Section titled “1.5.0 - 2026-10-10”

Bug fixes

Section titled “Bug fixes”
  • The forms of the control curve parameters of pywr v1 and v2 models no longer show a chart of the values
  • Show and highlight the name of a component that is not in the model in the metric and bathymetry fields, instead of showing the first name of the list
  • Keep the changes made to the document when a form with edits is saved, and fixed the values saved by the form
  • Do not move the state of a removed list item to the next item
  • Keep the edits made to a form while a checksum is computed
  • Do not request the preview of a file when no file is set
  • Always reply to a form when saving a component fails
  • Do not lose the entries of a dictionary while a key is typed in a form, and fixed other values saved by the forms
  • Accept only whole numbers in the form fields set to an integer
  • Do not blank the schematic when a results file has no time steps, and stop playing the time steps when other results or a live run are shown
  • Leave the connecting mode, the menu and the panel to add a node of the schematic only with the Escape key, and keep the selected nodes and edges when the model changes
  • Check the map library loaded by the schematic against its hash
  • The toolbar of the schematic can now be used with the keyboard
  • Reply to all the messages of the schematic so that it does not keep them in memory
  • Do not draw all the nodes and edges of the schematic again when one node is moved or selected
  • The results viewer no longer goes blank when two scenarios of a results file have the same label, and the QA report now draws the scenario that is picked
  • A scenario or a metric hidden in the legend of the results viewer can now always be shown again
  • The duration curve of a series with missing values now covers the whole time, for example when the results are compared with a shorter run
  • The QA report no longer asks to run the model again for the components that are not in the model anymore
  • The charts of the results viewer are no longer drawn again each time the zoom changes
  • The zoom of the results viewer is now reset when the results file is written again with other dates
  • The results viewer now says when the group filters hide all the checked scenarios
  • The charts of monthly results now have a tick for each month
  • The results viewer now lists the first 100 components of a large results file and the others are found with the filters
  • The names with characters outside Latin-1 are now written in the PDF of the QA report
  • The run summary now shows the time of the solver, the recorders and the components. The runner no longer crashes with a number of threads below 1 or too large for the machine.
  • A wide CSV results file with a repeated column no longer returns series with two values for each time step
  • The schematic and the forms no longer undo an edit or write a wrong JSON when the tab of the model is closed. An edit made straight after another change is no longer saved to a different component.
  • A file that changes in the background (for example a results file written by a run) no longer empties the trees and hides the status bar and the run button of the open model. The problems that were fixed are now removed from the models that are not in the active editor.
  • A pywr v2 model run without options now saves its results on Windows, where the name of the new folder was not valid. The empty folder of a run without outputs is now deleted.
  • A pywr v2 run now uses the Python modules in the folder of the model as they are saved, instead of the ones imported by the first run.
  • The errors are now written to the Pywr output channel with their message instead of an empty object. The warnings of the reference lookup are written to the same channel.
  • The prompts for a number no longer accept values such as 2.7 or 3abc, and the lookup of a new table no longer accepts 0 rows or columns.
  • A duplicated component name is now reported also when a component before it has no name.
  • Closing a schematic no longer stops the commands of another open schematic from working.
  • The trees are built faster for large models. The Python files of the workspace are no longer opened as documents to list their classes and functions.

1.4.1 - 2026-10-09

Section titled “1.4.1 - 2026-10-09”

Bug fixes

Section titled “Bug fixes”
  • Deleting a pywr v1 parameter, recorder or table no longer deletes the other components with the same configuration
  • The run of a pywr v2 model no longer freezes the editor and can be stopped with the Cancel button. The progress bar now advances with the time steps
  • The problems of a model are no longer missing when two models are opened or changed at the same time
  • The “Edit” action above a component now opens the right component when another one has the same configuration
  • Deleting a component no longer changes the formatting of the other components in the same list
  • A pywr v1 model is now normalised only when it is opened and not while it is edited
  • The forms, the search view and the schematic now have a Content Security Policy, and the text of the search is escaped in the search view
  • The extension no longer keeps in memory the theme listener of a closed schematic and the schema of a closed model
  • Answering “No” or “Show me where it’s used” when deleting a component that is still used no longer asks to confirm the deletion again
  • The actions above the components and the deletion of several nodes from the schematic are faster in large models
  • The zoom and the position of a schematic are now saved for each workspace, so that models with the same path in different workspaces no longer share them

1.4.0 - 2026-10-08

Section titled “1.4.0 - 2026-10-08”

Features

Section titled “Features”
  • The risk analyser is now implemented for pywr v1 models and can be run by clicking the “Run” button in VSCode. The tool exports the run raw data as well as percentiles, and generate charts for all model reservoirs
  • The schematic can now run pywr v1 and v2 models live with the “Run live” button. Step through the run or play it to see the flow of each node and the volume of the storage nodes without a results file. A node at its maximum flow gets an orange outline and an output node with a deficit a red outline with the missing flow

1.3.4 - 2026-10-07

Section titled “1.3.4 - 2026-10-07”

Features

Section titled “Features”
  • Added commands to create Python scripts: run a pywr v1 or v2 model, open the HDF5 file of a DataFrameParameter, open a TablesRecorder file with h5py, and a documented custom parameter in Python and Cython for pywr v1

1.3.3 - 2026-10-06

Section titled “1.3.3 - 2026-10-06”

Features

Section titled “Features”
  • The QA report is available for pywr v1 models: the nodes and the named parameters on the charts are exported with a TablesRecorder added by the run script. Each model format now declares how it supports the report, and the components that are not in the model anymore are not exported
  • Added the website of the extension, built with Astro and Starlight: a landing page with the features drawn along a river, the theme of the documentation, and the scripts that write the changelog page, optimise the screenshots and check that every command, setting and shortcut is documented
  • Compiled Cython modules can be loaded in pywr v1 models. The modules are set in the pywr.v1.cythonModules setting of the workspace, with the “Manage Cython Modules” command or by right-clicking a .so or .pyd file in the Explorer, and are imported by the run script before the model is loaded. The classes they register in pywr are collected with the selected Python environment and are recognised as custom components when the model is validated
  • Virtual storages are now rendered on the schematic for a pywr1 model and show the dependence from other nodes

Bug fixes

Section titled “Bug fixes”
  • When the Python Environments extension only returns a global interpreter, the environment set in python.defaultInterpreterPath or a .venv folder next to the model or in the workspace is used to run the model
  • Change the “Results” and “Virtual nodes” icon colour as the icon was blue on blue background and icon was therefore not fully visible
  • When the status bar flags there are model validation errors, the click action now focus on the Problem panel

1.3.1 - 2026-10-05

Section titled “1.3.1 - 2026-10-05”

Features

Section titled “Features”
  • The schematic shows a relative storage (pywr v2 ProportionalVolume, or a pywr v1 volume not above 1) as a percentage and uses it for the storage bar. The attribute of the result is shown next to the value of a node
  • Added a dropdown on the schematic nodes to change the result attribute when a pywr v2 node exports more than one
  • Added warnings for pywr v2 models that the schema cannot check: nodes with no edges, edge slots a node does not have, unused parameters, tables and timeseries, metric sets not saved by an output, lists with lengths that do not match and scenario groups not matching their size. The warnings do not mark the model as having errors
  • Added the “Run the model with options” command to pick the solver, the scenarios to run and the output folder, remembered for each model. The pywr v2 runner is built with the HiGHS, CBC and microlp solvers in addition to CLP. The model is saved before it is run
  • Added typed editors for the pywr v1 fields edited as JSON (index columns, dates to parse, sheet name, row index, optimisation bounds of the profiles and slot factors set as a parameter). The solver and the scenario combinations can be set in the model settings form
  • When the schematic is empty (i.e. it contains no nodes), the user is now asked to select which schematic type they would like to open: default to set the node x and y coordinates or the map to set lat and long coordinates
  • The pywr v2 runner can change the model before it is run and run without showing the results message, and returns the output folder
  • Added the QA report for pywr v2 models: charts saved next to the model (model.qa.json) with the components to check. The report runs a copy of the model to export only those components, draws the charts with custom line colours and styles, and exports them as PDF

Bug fixes

Section titled “Bug fixes”
  • Fixed the test:run command, which did not compile the extension
  • The results of a pywr v2 run could not be opened because the output files were not closed at the end of the run
  • The map no longer reloads or shifts when a node is moved.

1.3.0 - 2026-10-04

Section titled “1.3.0 - 2026-10-04”

Features

Section titled “Features”
  • Added package icon and improved marketplace metadata
  • When user click on an item in the search panel, it now opens the edit form. An inline icon allows the user to go to the JSON configuration block
  • Added rename, go to definition, references, hover, completion, symbols, quick fixes and code lens actions for the model JSON
  • Sync the selection between the schematic and the Network tree. The search matches the component types and shows a result on the schematic
  • Added the new model command, keybindings, a walkthrough and right-click menus in the trees. The run command works when a schematic or a form has the focus

Bug fixes

Section titled “Bug fixes”
  • Do not report the files written by the pywr v1 CSV and tables recorders as missing

  • Link results to the model, add analysis views and preview data in the forms
  • Show the results on the schematic and the dependencies of a component
  • Edit the row and column of table metrics in the forms
  • Added forms for edges and model settings, and checksum computation
  • Open forms and run tree actions from the schematic
  • Open the form after adding a component

Section titled “Bug fixes”

  • Align the pywr v1 schema and forms with the keys pywr loads
  • Suggest the columns of pywr-1 tables and edit their index columns as a list
  • Exclude build scripts from vscode package
