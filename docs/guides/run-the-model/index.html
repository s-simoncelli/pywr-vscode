Run the model

You run a model with one button. This page covers what you need first, what happens during and after a run, and how to change the way a model runs without editing it.

Before the first run

Section titled “Before the first run”

A run needs a Python environment selected in VS Code. If you have not done it yet, follow Set up Python to run models. In short:

  • Pywr v2
  • Pywr v1
  • A virtual or conda environment with Python 3.10 or later. - Pywr itself is built into the extension: there is nothing else to install, unless your model reads timeseries with pandas or uses your own Python parameters.
  • A virtual or conda environment with pywr 1 installed (pip install pywr).
  • The model runs with pywr from that environment. - If your own components are compiled with Cython, add the modules first. See Use Cython modules.

Then run Python: Select Interpreter from the Command Palette and pick the environment.

Your model must also say what to save, or the run leaves nothing to chart:

  • Pywr v2 an output, of type HDF5 or CSV, that saves a metric set
  • Pywr v1 a CSV recorder or a tables recorder

The templates already have one.

Run

Section titled “Run”

  1. Open the model. The JSON file, its schematic or one of its forms can have the focus.

  2. Press the Run button, the triangle at the top right of the editor. You can also press Ctrl Alt P, then R, or run Pywr: Run the model and save its outputs from the Command Palette.

    The model is saved first, so the run always uses what you see.

  3. Follow the progress in the notification at the bottom right. It shows the percentage and the time step the run has reached. Press Cancel to stop the run.

  4. When the run completes, the notification shows how long it took and offers what to do next.

After the run

Section titled “After the run”
Button What it does
Open results Opens the results in the results viewer. It is there when the run wrote an HDF5 or a CSV file.
Show summary Opens a table with how long each part of the run took.
Open output folder Opens the folder with the files of the run.

Where the results are saved

Section titled “Where the results are saved”
  • Pywr v2
  • Pywr v1

Each run saves its files in a new folder named after the date and the time of the run, inside a results folder next to the model:

Earlier runs are kept, so you can compare two runs.

Pywr v1 saves the results where the CSV and the tables recorders of your model say, in their url. Open output folder opens the folder of those files, and asks which one when the recorders write to more than one folder.

The summary lists the version of pywr, the solver, the number of time steps and scenarios, the run time and the speed.

Run with options

Section titled “Run with options”

To change how a model runs without editing it, use Run the model with options.

  1. Press the gear button next to Run, or press Ctrl Alt

    P, then Shift R, or run Pywr: Run the model with options….

  2. Change the options you need. The list stays open until you run or close it.

    Option What you can set
    Solver The solver to use, or Default.
    Output folder The folder where the outputs are saved, instead of a new folder in results.
    Scenarios to run For each scenario group, the scenarios to run instead of all of them.

  3. Pick Run the model.

The options are remembered for each model, and used again the next time you run with options. Pick Reset the options to go back to the defaults. The model file is never changed.

Run only some scenarios

Section titled “Run only some scenarios”

Pick a scenario group in the list and type the scenarios to run:

  • a range, as start:end, counting from 0 and leaving out the end. 0:2 runs the first two scenarios.
  • Pywr v2 a list of positions, such as 0, 2, 4.

Solvers

Section titled “Solvers”
Solvers
Pywr v2 CLP (the default), HiGHS, CBC and microlp
Pywr v1 GLPK, GLPK edge and lp_solve. The solver must be available in your installation of pywr.

Pywr v1 You can also save the solver and the scenario combinations in the model itself, from the model settings.

Use more or fewer threads

Section titled “Use more or fewer threads”

Pywr v2 A model with scenarios runs them in parallel. Set how many threads to use with the pywr.runner.threads setting. The default is 3; the most you can use depends on your machine.

When a run fails

Section titled “When a run fails”

A failed run shows an error notification. For a Pywr v1 model, Show details opens the full message from Python.

The most common causes are about the Python environment. See Troubleshooting for each message and its fix.

Tip

To check after each change that the model still behaves as you expect, define a QA report: it runs the model and draws the same charts every time.
